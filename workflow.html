Workflow Illustration

This document describes a standard workflow for exploratory modeling.

Imagine you’re in charge of admissions at a large university. You want to know if your admissions process is fair. You’ve got data from thousands of individual applicants. What now?

Step 1: Conceptual Model

This first step is to define your conceptual model. A conceptual model includes no numbers, just a visual representation of the different variables you want to include and the relationships between them. You’ll hear people call this kind of visualization a DAG (Directed Acyclic Graph), but

dag { Admitted [outcome,pos="-0.619,0.077"] Department [exposure,pos="-0.858,0.192"] Sex [exposure,pos="-1.059,-0.272"] UNKNOWN [latent,pos="-0.414,0.077"] Department -> Admitted Sex -> Admitted Sex -> Department UNKNOWN -> Admitted }

How should you pick these variables? You need to use your intuitions.

This is a process of exploration. There’s no right answer, only better and better representations of the story you want to understand. If your model doesn’t work, don’t worry: you’ll know soon enough, and you’ll find another that will.

Here, we’re choosing sex as a variable because we know that sex-based discrimination is a major social issue. We’ll also look at department because we know that some departments are harder to get into others.

Based on that, we might wonder: if women are admitted to the college at a lower rate, is that a direct effect of discrimination or is it an indirect effect of the departments they’re chosing to apply to. Both represent forms of discrimination, but they require different interventions to fix. Statistics can help us understand the dynamic at play.

Visually, we might represent this question as the graph above.

Step 2: Formal Model

The next step is to give our model a formal definition.

\[ \begin{align} admitted_i &\sim \mathrm{Bernoulli}(p_i) \\ \mathrm{logit}(p_i) &= \alpha + \beta_{\mathrm{sex}[i]} + \gamma_{\mathrm{dept}[i]} + \delta_{\mathrm{sex}[i],\,\mathrm{dept}[i]} \\ \alpha &\sim \mathrm{Normal}(0, 1.5) \\ \beta_{\mathrm{sex}} &\sim \mathrm{Normal}(0, 1) \\ \gamma_{\mathrm{dept}} &\sim \mathrm{Normal}(0, 1) \\ \delta_{\mathrm{sex},\,\mathrm{dept}} &\sim \mathrm{Normal}(0, 0.5) \end{align} \]

We need to make a few choices here. First, we need to have a clear sense of what we’re trying to understand by now (our estimand), because we’ll need to define parameters to get us there. We’ll also need to set our prior beliefs.

The result looks complicated, but it’s really just a few parts:

  1. A likelihood function (1st line), explaining our randomness
  2. A linear predictor (2nd line), explaining how our outcome is predicted
  3. Prior estimates (Lines 3-6), explaining what we currently believe

Step 3: Computational Model

The next step requires us to get a bit technical. We’re going to turn our formal model into something that computers can use.

models/berkeley.stan
data {
  // dimensions
  int<lower=1> n;
  int<lower=1> n_sex;
  int<lower=1> n_dept;
  
  // observed outcomes
  array[n] int<lower=0, upper=1> admitted;
  
  // group indices
  array[n] int<lower=1, upper=n_sex> sex;
  array[n] int<lower=1, upper=n_dept> dept;
  
  // prior predictive toggle (skips likelihood calculations)
  int<lower=0, upper=1> prior_only;
}
parameters {
  real alpha;
  sum_to_zero_vector[n_sex] beta;
  sum_to_zero_vector[n_dept] gamma;
  sum_to_zero_matrix[n_sex, n_dept] delta;
}
model {
  alpha ~ normal(0, 1.5);
  beta ~ normal(0, 1);
  gamma ~ normal(0, 1);
  to_vector(delta) ~ normal(0, 0.5);
  
  if (!prior_only) {
    vector[n] eta;
    for (i in 1 : n) 
      eta[i] = alpha + beta[sex[i]] + gamma[dept[i]] + delta[sex[i], dept[i]];
    admitted ~ bernoulli_logit(eta);
  }
}
generated quantities {
  // prior/posterior predictive draws
  array[n] int admitted_sim;
  for (i in 1 : n) {
    real eta = alpha + beta[sex[i]] + gamma[dept[i]] + delta[sex[i], dept[i]];
    admitted_sim[i] = bernoulli_logit_rng(eta);
  }
}

One nice feature of Bayesian modeling is that we can use exactly the same definitions for our generative models and for our statistical models.

library(rlang)

replace_indexes <- function(tbl, data, ...) {
  specs <- rlang::enquos(...)
  factor_levels <- lapply(data, levels)

  parse_spec <- function(q) {
    expr <- rlang::get_expr(q)

    if (rlang::is_symbol(expr)) {
      return(list(var = rlang::as_string(expr), dims = NULL))
    }

    if (rlang::is_call(expr, "[")) {
      var <- rlang::as_string(expr[[2]])
      dims <- vapply(as.list(expr)[-c(1, 2)], rlang::as_string, character(1))
      return(list(var = var, dims = dims))
    }

    stop("Invalid specification")
  }

  parsed <- lapply(specs, parse_spec)
  out <- tbl

  for (p in parsed) {
    var <- p$var
    dims <- p$dims
    if (is.null(dims)) {
      next
    }

    idx_pattern <- paste(rep("(\\d+)", length(dims)), collapse = ",")
    full_pattern <- paste0("^", var, "\\[", idx_pattern, "\\]$")

    out$variable <- vapply(
      out$variable,
      function(v) {
        if (!grepl(paste0("^", var, "\\["), v)) {
          return(v)
        }

        m <- stringr::str_match(v, full_pattern)
        if (all(is.na(m))) {
          return(v)
        }

        idx <- as.integer(m[1, -1])

        labels <- Map(
          function(dim, i) {
            lvls <- factor_levels[[dim]]
            if (is.null(lvls) || i > length(lvls)) {
              return(NA_character_)
            }
            lvls[i]
          },
          dims,
          idx
        )

        paste0(var, "[", paste(unlist(labels), collapse = ","), "]")
      },
      character(1)
    )
  }

  out
}

Step 4: Simulation

Now, we’re going to use our model to generate simulated data. The results don’t tell us anything about the world, but this is nevertheless an important step because it allows us to test the assumptions of our model to see if the outputs we get are coherent.

Mechanically, the key difference between this step and the next one is that here we’ll tell our model to skip the likelihood calculations. The predictions we make here are based purely on our prior estimates. In the next step, we’ll use likelihoods to make predictions on the basis of our posterior estimates.

Show code 
# fit the data
fit <- df |>
  compose_data() |>
  list_assign("prior_only" = 1) |>
  model$sample()

Step 5: Fitting

We did it! These are our results, at least in raw form. This time, we’ll tell our model to apply our likelihood function to the data we actually observed. Through this, we are able to update our prior beliefs to posterior distributions, which can hopefully be transformed to tell us something about the world.

Step 6: Interpretation

This is where we can get really creative again. We’ve fitted our model, so now what? We’ve got updated posterior distributions for all of our parameters, and we can do a lot. The parameters by themselves can be useful, but more interesting even is the way we can use these parameters to estimate more complex phenomena, simulate counterfactual data, and test potential interventions.

Once we’ve got the mechanics in place, this is where I hope we can spend most of our time together.
