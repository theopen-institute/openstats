A Bayesian Workflow

This document walks through a complete Bayesian workflow, from the first question to a result we can defend.

Imagine you’re in charge of admissions at a large university. You want to know if your admissions process is fair. You’ve got data from thousands of individual applicants. What now?

The workflow starts with a preliminary step, and then has ten steps in three parts.

  • Data exploration: where the data came from, before we ask them anything.
    1. Get to know the data. Find out how the data came to exist: who is in them, who isn’t, and how each variable was recorded. Look at the variables, but not yet at how the outcome relates to the exposure.
  • Scientific model: what we believe about the world, before any statistics.
    1. Ask the question. Say in plain words what you want to know, and picture what the answer would look like.
    2. Draw the causal model (DAG). Write down what you assume causes what, based on what you know about the domain.
    3. Define the estimand. Use the DAG to turn your question into one exact number, before you touch the data.
    4. Simulate the population. Write a simulation that could produce data like yours.
  • Statistical model: the machinery that turns data into an estimate, tested where we already know the truth.
    1. Write the formal model. Derive the statistical model from the DAG, in math notation.
    2. Write the Stan code. Translate the formal model into a program.
    3. Test on simulated data. Check that the priors imply plausible data and that the model recovers parameters we already know.
  • Analysis: the real data, the estimate, and how far to trust it.
    1. Fit and validate the model. Run the sampler, check its diagnostics, and run posterior predictive checks. Can we trust the model?
    2. Compute the estimate. Use the fitted model to estimate the estimand from step 3.
    3. Test its robustness. How much does the estimate depend on our assumptions?

Nothing before Step 8 looks at how the outcome relates to the exposure: here, at how admission differs between men and women. Step 0 looks at the data, but not at that comparison. In principle, you could do steps 1–7 before collecting any data. Step 0 would then be planning how they’ll be produced.

The steps are numbered, but the workflow is a loop. If the model can’t recover known parameters in step 7, or can’t reproduce the data in step 8, go back and fix the statistical model. If the result in step 10 depends on an assumption you can’t defend, go back further, to the scientific model: the DAG or the simulation. Some failures send us all the way back to Step 0, for example when a result turns out to depend on how something was measured, or on who ended up in the data. Each of those failures teaches us something. This document goes around the loop once: Step 8 finds a flaw in the model, and we go back to Step 5 to fix it.

# ---- Stan index labels -----------------------------------------------------------
replace_indexes <- function(tbl, data, ...) {
  specs <- rlang::enquos(...)
  factor_levels <- lapply(data, levels)

  parse_spec <- function(q) {
    expr <- rlang::get_expr(q)

    if (rlang::is_symbol(expr)) {
      return(list(var = rlang::as_string(expr), dims = NULL))
    }

    if (rlang::is_call(expr, "[")) {
      var <- rlang::as_string(expr[[2]])
      dims <- vapply(as.list(expr)[-c(1, 2)], rlang::as_string, character(1))
      return(list(var = var, dims = dims))
    }

    stop("Invalid specification")
  }

  parsed <- lapply(specs, parse_spec)
  out <- tbl

  for (p in parsed) {
    var <- p$var
    dims <- p$dims
    if (is.null(dims)) {
      next
    }

    idx_pattern <- paste(rep("(\\d+)", length(dims)), collapse = ",")
    full_pattern <- paste0("^", var, "\\[", idx_pattern, "\\]$")

    out$variable <- vapply(
      out$variable,
      function(v) {
        if (!grepl(paste0("^", var, "\\["), v)) {
          return(v)
        }

        m <- stringr::str_match(v, full_pattern)
        if (all(is.na(m))) {
          return(v)
        }

        idx <- as.integer(m[1, -1])

        labels <- Map(
          function(dim, i) {
            lvls <- factor_levels[[dim]]
            if (is.null(lvls) || i > length(lvls)) {
              return(NA_character_)
            }
            lvls[i]
          },
          dims,
          idx
        )

        paste0(var, "[", paste(unlist(labels), collapse = ","), "]")
      },
      character(1)
    )
  }

  out
}

# Draw a DAG as a ggplot: a circle per variable, an arrow per direct cause.
#   edges:      c("S -> H", "H -> W")
#   pos:        list(S = c(0, 0), H = c(1, 1), W = c(2, 0))
#   labels:     full names drawn beside each node, e.g. c(S = "Sex")
#   above:      nodes whose label goes above the circle instead of below
#   left, right: nodes whose label goes beside the circle instead
#   highlight:  edges to draw in red (e.g. one path); the rest fade to gray
#   exposure, outcome, unobserved: node names to style
dag_plot <- function(
  edges,
  pos,
  labels = NULL,
  above = NULL,
  left = NULL,
  right = NULL,
  highlight = NULL,
  exposure = NULL,
  outcome = NULL,
  unobserved = NULL,
  r = 0.3,
  text_size = 9
) {
  ink <- INK
  blue <- BLUE
  red <- RED
  gray <- GRAY

  nodes <- tibble::tibble(
    name = names(pos),
    x = vapply(pos, `[`, numeric(1), 1),
    y = vapply(pos, `[`, numeric(1), 2)
  )
  nodes$fill <- ifelse(
    nodes$name %in% exposure,
    blue,
    ifelse(nodes$name %in% outcome, ink, "white")
  )
  nodes$text <- ifelse(nodes$fill == "white", ink, "white")
  nodes$linetype <- ifelse(nodes$name %in% unobserved, "dashed", "solid")
  nodes$label <- if (is.null(labels)) "" else unname(labels[nodes$name])
  nodes$label[is.na(nodes$label)] <- ""
  nodes$label_y <- ifelse(nodes$name %in% above, nodes$y + r + 0.12, nodes$y - r - 0.12)
  nodes$vjust <- ifelse(nodes$name %in% above, 0, 1)
  nodes$label_x <- nodes$x
  nodes$hjust <- 0.5
  side <- nodes$name %in% left
  nodes$label_x[side] <- nodes$x[side] - r - 0.12
  nodes$hjust[side] <- 1
  side <- nodes$name %in% right
  nodes$label_x[side] <- nodes$x[side] + r + 0.12
  nodes$hjust[side] <- 0
  side <- nodes$name %in% c(left, right)
  nodes$label_y[side] <- nodes$y[side]
  nodes$vjust[side] <- 0.5

  circles <- do.call(rbind, lapply(seq_len(nrow(nodes)), function(i) {
    t <- seq(0, 2 * pi, length.out = 61)
    data.frame(
      name = nodes$name[i],
      x = nodes$x[i] + r * cos(t),
      y = nodes$y[i] + r * sin(t),
      fill = nodes$fill[i],
      linetype = nodes$linetype[i]
    )
  }))

  # Arrows run between circle edges, not centers
  ends <- strsplit(gsub("\\s", "", edges), "->")
  from <- vapply(ends, `[`, character(1), 1)
  to <- vapply(ends, `[`, character(1), 2)
  x0 <- nodes$x[match(from, nodes$name)]
  y0 <- nodes$y[match(from, nodes$name)]
  x1 <- nodes$x[match(to, nodes$name)]
  y1 <- nodes$y[match(to, nodes$name)]
  len <- sqrt((x1 - x0)^2 + (y1 - y0)^2)
  gap <- r + 0.04
  arrows <- data.frame(
    x = x0 + (x1 - x0) * gap / len,
    y = y0 + (y1 - y0) * gap / len,
    xend = x1 - (x1 - x0) * gap / len,
    yend = y1 - (y1 - y0) * gap / len,
    color = if (is.null(highlight)) {
      ink
    } else {
      ifelse(paste0(from, "->", to) %in% gsub("\\s", "", highlight), red, gray)
    }
  )

  ggplot2::ggplot() +
    ggplot2::geom_segment(
      data = arrows,
      ggplot2::aes(x, y, xend = xend, yend = yend, color = I(color)),
      linewidth = 1.6,
      arrow = ggplot2::arrow(length = ggplot2::unit(0.18, "inches"), type = "closed")
    ) +
    ggplot2::geom_polygon(
      data = circles,
      ggplot2::aes(x, y, group = name, fill = I(fill), linetype = I(linetype)),
      color = ink,
      linewidth = 1.2
    ) +
    ggplot2::geom_text(
      data = nodes,
      ggplot2::aes(x, y, label = name, color = I(text)),
      size = text_size,
      fontface = "bold"
    ) +
    ggplot2::geom_text(
      data = nodes,
      ggplot2::aes(label_x, label_y, label = label, hjust = hjust, vjust = vjust),
      color = ink,
      size = text_size * 0.75
    ) +
    ggplot2::coord_equal(clip = "off") +
    ggplot2::scale_x_continuous(
      expand = ggplot2::expansion(add = c(
        if (is.null(left)) 0.6 else 1.8,
        if (is.null(right)) 0.6 else 1.8
      ))
    ) +
    ggplot2::scale_y_continuous(expand = ggplot2::expansion(add = 0.6)) +
    ggplot2::theme_void()
}

# ---- The three DAG building blocks, drawn the same way everywhere --------------
#   fork:     X <- Z -> Y
#   pipe:     X -> Z -> Y
#   collider: X -> Z <- Y
# direct = TRUE adds the arrow X -> Y. Other arguments (highlight, unobserved, ...)
# go to dag_plot().
fork_dag <- function(x = "X", z = "Z", y = "Y", labels = NULL, direct = FALSE, ...) {
  dag_plot(
    c(paste(z, "->", x), paste(z, "->", y), if (direct) paste(x, "->", y)),
    stats::setNames(list(c(0, 0), c(1, 1.1), c(2, 0)), c(x, z, y)),
    labels = labels, above = z, exposure = x, outcome = y, ...
  )
}

pipe_dag <- function(x = "X", z = "Z", y = "Y", labels = NULL, direct = FALSE, ...) {
  dag_plot(
    c(paste(x, "->", z), paste(z, "->", y), if (direct) paste(x, "->", y)),
    stats::setNames(list(c(0, 0), c(1, 1.1), c(2, 0)), c(x, z, y)),
    labels = labels, above = z, exposure = x, outcome = y, ...
  )
}

collider_dag <- function(x = "X", z = "Z", y = "Y", labels = NULL, direct = FALSE, ...) {
  dag_plot(
    c(paste(x, "->", z), paste(y, "->", z), if (direct) paste(x, "->", y)),
    stats::setNames(list(c(0, 1.1), c(1, 0), c(2, 1.1)), c(x, z, y)),
    labels = labels, above = c(x, y), exposure = x, outcome = y, ...
  )
}

Data exploration

Step 0: Get to know the data

Before we ask anything of the data, we find out how they came to exist. A dataset is not a window onto the world. Someone decided whom to include, what to record and how to record it, and each of those decisions shapes what we can learn.

Where the data came from. In fall 1973, the Graduate Division of the University of California, Berkeley, made admission decisions for 12,763 applicants to its 101 departments. Bickel, Hammel and O’Connell analysed them in the journal Science in 1975.1 Our file holds only part of that: the applicants to the six largest departments, labeled A to F. This is the version that is widely shared, and it matches R’s built-in UCBAdmissions table exactly. We don’t have to take that on trust:

Who is in it, and who isn’t. Each row is one application to one department, 4,526 in all. Just as important is what the data leave out.

  • Only six departments. The rest of the university isn’t here, so our conclusions are about these six.
  • Only people who applied. Anyone who was discouraged from applying, or couldn’t afford to, never appears. We’ll come back to this in Step 10.
  • We can’t tell whether anyone appears twice. There’s no applicant ID, so someone who applied to two departments could be two rows. We don’t know, and that’s worth knowing.

What was measured, and how. Three columns: dept, the department applied to; sex, the sex recorded for the applicant (male or female); and admitted, 1 if they were admitted and 0 if not. Nothing is missing. Nothing about qualifications was recorded: no grades, test scores or letters. We’ll see in Step 2 why that matters.

Who applied where. How many men and women applied, how each sex’s applications spread across the departments, and how selective each department is, counting all its applicants together:

Men applied mostly to departments A and B, the two that admit most of their applicants. Women applied mostly to C–F, which admit far fewer.

There is one rule for this step: we don’t look at how admission differs between men and women. That comparison is the answer we’re trying to estimate. If we saw it now, we could no longer choose a model for it honestly. Everything else is fair game. With these data the rule is partly make-believe: they’re a textbook example, and you may already know how the story ends. With your own data you won’t, and the rule is what keeps the analysis honest.

Scientific model

Step 1: Ask the question

Start with the question as you’d say it out loud: is our admissions process unfair to women? You don’t need technical terms yet. You do need a clear picture of what the answer would look like.

A good way to get one is a thought experiment. Take a single applicant and change only the sex on their form. Keep their grades, their letters and the department they applied to the same. Would their chance of getting in change? If it would, the process treats people differently because of their sex. That’s what we mean by unfair.

We can’t run this experiment on real applicants, but it tells us what we’re looking for. We’ll come back to it in Step 4, where we run it on a simulated population.

Step 2: Draw the causal model (DAG)

A causal model contains no numbers. It’s a picture of the variables and of which ones cause which. You’ll hear it called a DAG (Directed Acyclic Graph), which is a complicated name for a simple idea.

dag { Admitted [outcome,pos="-0.619,0.077"] Department [adjusted,pos="-0.858,0.192"] Sex [exposure,pos="-1.059,-0.272"] Department -> Admitted Sex -> Admitted Sex -> Department }

Sex is the exposure, the cause we’re asking about, and admission is the outcome. Department is drawn as adjusted: as Step 3 explains, we’ll compare men and women who applied to the same department.

How do you pick these variables? You use what you already know about the subject. Here, we include sex because sex-based discrimination is a major social issue. We include department because some departments are much harder to get into than others.

These are theoretical choices, not empirical ones. The data can’t tell us which variables we should put in the graph or which way the arrows should point. We make these decisions on the basis of our past experience, previous research, and the consensus of the field. Very different DAGs can fit the same data equally well. The DAG comes from our understanding of how admissions work, and we have to commit to it before the data can say anything.

The choices also decide the answer. Every arrow is an assumption, and every missing arrow is an assumption too, usually a stronger one. Together they determine which variables the model includes, which comparison we make, and what the final number means. Suppose we had left department out. The DAG would then say to compare overall admission rates for men and women, and that comparison gives a very different answer from the one we’ll get here. Change the DAG and you will almost certainly change the result.

The DAG also leaves things out, starting with what Step 0 found the data don’t record. Many other factors affect admission. The most obvious is an applicant’s qualifications: their undergraduate grades, test scores, letters of recommendation and research experience. Others include how well their interests match a faculty member’s, whether they need funding, and how they come across in an interview. A factor that affects admission is safe to leave off the graph only if it’s unrelated both to sex and to where people apply. Qualifications can fail on either count. They may differ between the men and women who apply: if women face barriers that only the most qualified overcome, the women who apply are more qualified than the men. And they may affect where people apply: strong applicants may aim for the more selective departments. Since sex affects where people apply too, the men and women who end up in the same department then got there for different reasons, and can differ in qualifications. Either way, because we compare men and women within departments, a factor like that can create a gap between them even when there’s no discrimination. So we’re assuming that, within each department, the men and women who apply are equally qualified. That’s a strong assumption, and the data can’t check it for us. In Step 10 we’ll see how much the result moves if it’s wrong.

This DAG is not the final word, and no DAG ever will be. There is no “right” model waiting to be found at the end of the process. Every DAG is a simplification. Each one brings some parts of the problem into focus and leaves others out. This one helps us see how department choice can hide or create a gap between men and women. It says nothing about what happens before anyone applies: who is encouraged to apply, who can afford to, and who expects to be welcome. A different DAG would bring those questions into view and push others out.

That doesn’t mean every DAG is as good as any other. Some fit what we know far better, and the data can rule some out. But the value of this workflow comes from going around the loop: drawing a DAG, seeing what it implies, finding where it fails, and drawing a better one. Each pass shows us something about the problem that we couldn’t see before. We never finish. We just understand more each time.

Step 3: Define the estimand

The DAG shows that our plain-language question has more than one meaning. Sex reaches admission along two paths:

  • A direct path, \(\text{Sex} \to \text{Admitted}\): departments treat women differently from men who apply to the same department.
  • An indirect path, \(\text{Sex} \to \text{Department} \to \text{Admitted}\): women apply to different departments, and those departments admit fewer people.

Suppose women are admitted at a lower rate overall. That gap could come from either path, and each one calls for a different fix. So “is admissions unfair?” is still too vague to estimate. We have to choose which path we’re asking about.

We choose based on what we’re responsible for, not on what’s easiest to estimate. As the admissions office, we control the decisions departments make, so we’ll focus on the direct path. This is the thought experiment from Step 1: change the applicant’s sex and keep their department the same. Written as a number to estimate, it’s the estimand:

Estimand: for each applicant, how much their chance of admission would change if the department saw them as a woman rather than as a man, with everything else about them, their department included, left as it is; averaged over all applicants.

We’ll measure it as a difference in admission rates. For example, a result of −0.05 would mean that being seen as a woman lowers an applicant’s chance of admission by 5 percentage points.

“Averaged over all applicants” is a choice too. It counts each department in proportion to how many people apply to it. We could instead average over the women who applied. That asks what the process did to the women who actually came, rather than how it treats applicants in general, and it counts departments C–F, where most women applied, much more. If every department treats women the same way, the two versions give the same number. If departments differ, they can give very different numbers, so we choose now, before the data can tempt us. As the admissions office, we’re responsible for how the process treats everyone who applies, so we average over all applicants.

Comparing applicants to the same department means we have to condition on department, so department has to go into the model. Settling the estimand before we write any code tells us what the model has to include and what we’ll compute from it at the end.

Step 4: Simulate the population

Before writing a statistical model, we write a generative one: a simulation that follows the DAG and produces fake applicants. This makes us state precisely how we think the data come about. Later, it gives us data where we know the right answer.

The simulation’s default numbers come from the tables in Step 0: where men and women applied, and each department’s admission rate for all its applicants together. Neither shows how admission differs between men and women. (A stricter rule would rule out even the departments’ admission rates, and we’d have to make them up. We’ve drawn the line at the comparison we’re trying to estimate.)

Show code 
# Each assumption is an argument, with a default based on the real data. Change them to
# simulate a different world. discrimination, admit_rate, male_pref and female_pref give
# one value per department, in the order of depts, or a single value for all of them:
# admit_rate = 0.4 means every department admits 40%.
simulate_admissions <- function(
  n = 4500,
  discrimination = 0, # Sex -> Admitted: effect of being female, in log-odds
  depts = c("A", "B", "C", "D", "E", "F"),
  admit_rate = c(0.65, 0.60, 0.35, 0.33, 0.25, 0.07), # Department -> Admitted
  male_pref = c(0.31, 0.21, 0.12, 0.15, 0.07, 0.14), # Sex -> Department
  female_pref = c(0.06, 0.02, 0.32, 0.20, 0.21, 0.19) # Sex -> Department
) {
  # one row per department (single values are recycled to every department)
  departments <- tibble(
    dept = fct(depts),
    discrimination,
    admit_rate,
    male_pref,
    female_pref
  )

  # Sex: 60% men, as in the real data
  sex <- sample(fct(c("male", "female")), n, replace = TRUE, prob = c(0.6, 0.4))

  # Sex -> Department
  dept <- if_else(
    sex == "female",
    sample(departments$dept, n, replace = TRUE, prob = departments$female_pref),
    sample(departments$dept, n, replace = TRUE, prob = departments$male_pref)
  )

  # Department, Sex -> Admitted
  d <- match(dept, departments$dept)
  dept_rate <- departments$admit_rate[d]
  dept_discrimination <- departments$discrimination[d]
  log_odds <- qlogis(dept_rate) + dept_discrimination * (sex == "female")
  admitted <- rbinom(n, 1, plogis(log_odds))

  tibble(dept, sex, dept_rate, dept_discrimination, admitted)
}

Statistical model

Step 5: Write the formal model

Next, we turn the DAG into a statistical model:

\[ \begin{align} \text{admitted}_i &\sim \mathrm{Bernoulli}(p_i) \\ \mathrm{logit}(p_i) &= \alpha + \beta_{\mathrm{sex}[i]} + \gamma_{\mathrm{dept}[i]} \\ \alpha &\sim \mathrm{Normal}(0, 1.5) \\ \beta_{\mathrm{sex}} &\sim \mathrm{Normal}(0, 1) \\ \gamma_{\mathrm{dept}} &\sim \mathrm{Normal}(0, 1) \\ 0 &= \textstyle\sum_{\mathrm{sex}} \beta = \sum_{\mathrm{dept}} \gamma \end{align} \]

It looks complicated, but it has four parts:

  1. A likelihood (line 1): how randomness enters. Each applicant is admitted or not.
  2. A linear predictor (line 2): how the arrows in the DAG combine. There’s a baseline \(\alpha\), a sex effect \(\beta\), and a department effect \(\gamma\).
  3. Priors (lines 3–5): what we believe before we see the data.
  4. Constraints (line 6): each set of effects adds up to zero. Without this, the model couldn’t tell its parts apart. Adding 1 to \(\alpha\) and subtracting 1 from every \(\gamma\) would give exactly the same predictions. With the constraint, \(\alpha\) is the overall average and every other term is a deviation from it.

Each term in the model matches a piece of the DAG. Sex and department both point into admission, so both appear in the linear predictor. The estimand from Step 3 comes from \(\beta\), the term that lets women’s and men’s chances differ within a department.

The model also makes a simplifying assumption: the sex effect \(\beta\) is the same in every department. That keeps the model small. We’ll find out in Step 8 whether the data go along with it.

Step 6: Write the Stan code

Now we translate the formal model into a program the computer can run:

models/berkeley.stan
functions {
  // adjustment for sum_to_zero_vector[K] SDs
  real stz_correction(int K) {
    return inv_sqrt(1 - inv(K));
  }
}
data {
  // prior predictive toggle (skips likelihood calculations)
  int<lower=0, upper=1> prior_only;

  // prior scales
  real<lower=0> alpha_sd;
  real<lower=0> beta_sd;
  real<lower=0> gamma_sd;

  // dimensions
  int<lower=1> n;
  int<lower=1> n_sex;
  int<lower=1> n_dept;

  // group indices
  array[n] int<lower=1, upper=n_sex> sex;
  array[n] int<lower=1, upper=n_dept> dept;

  // observed outcomes
  array[n] int<lower=0, upper=1> admitted;
}
parameters {
  real alpha;
  sum_to_zero_vector[n_sex] beta;
  sum_to_zero_vector[n_dept] gamma;
}
model {
  alpha ~ normal(0, alpha_sd);
  beta ~ normal(0, beta_sd * stz_correction(n_sex));
  gamma ~ normal(0, gamma_sd * stz_correction(n_dept));

  vector[n] eta = alpha + beta[sex] + gamma[dept];
  if (!prior_only)
    admitted ~ bernoulli_logit(eta);
}
generated quantities {
  // admission probability for every sex x department cell
  matrix[n_sex, n_dept] p;
  for (s in 1 : n_sex)
    for (d in 1 : n_dept)
      p[s, d] = inv_logit(alpha + beta[s] + gamma[d]);
}

A few details:

  • The priors’ scales (alpha_sd, beta_sd, gamma_sd) come in as data, so we can change a prior without editing the model. We’ll do that in Step 10.
  • Stan enforces the constraints with sum_to_zero_vector. Forcing effects to sum to zero shrinks their spread, so the code widens each prior’s scale to compensate. That way, each effect’s prior matches the formal model.
  • The prior_only switch skips the likelihood. With it on, the model samples from the priors alone, which is what we need for prior predictive checks.
  • generated quantities reports the admission probability for every sex × department cell. We’ll compute the estimand from these.

We compile the model and write a small helper so every fit in this document uses the same settings:

fit_model <- function(data, model = berkeley, prior = priors, prior_only = 0) {
  data |>
    select(dept, sex, admitted) |>
    compose_data() |>
    c(list(prior_only = prior_only), prior) |>
    model$sample(
      seed = 2026,
      parallel_chains = 4, # run the four chains at once
      adapt_delta = 0.95, # smaller steps, for the tricky geometry of Step 8's second model
      refresh = 0,
      show_messages = FALSE
    )
}

# the estimand from Step 3, computed for every posterior draw: the female − male
# difference in each department, averaged over the applicants in weight_by
direct_effect <- function(fit, data = df, weight_by = data) {
  weights <- weight_by |>
    count(dept, .drop = FALSE) |>
    mutate(w = n / sum(n)) |>
    pull(w)

  fit |>
    spread_draws(p[sex, dept]) |>
    mutate(sex = levels(data$sex)[sex]) |>
    pivot_wider(names_from = sex, values_from = p) |>
    mutate(w = weights[dept]) |>
    group_by(.draw) |>
    summarise(direct_effect = sum(w * (female - male)))
}

The prior on the direct effect is centered on zero, so it doesn’t assume discrimination in either direction. It’s also wide: gaps of 50 percentage points or more either way are allowed.

The admission rates show a problem. The priors pile up near 0% and 100%. That happens because three Normal priors add up on the log-odds scale, and a log-odds of ±3 is already 5% or 95%. These priors are looser than our actual knowledge: we don’t believe departments admit nearly everyone or nearly no one. This is a judgment call. We could tighten \(\alpha\) and \(\gamma\) now. With thousands of applicants, we expect the data to outweigh the priors, so we’ll keep them and check that expectation directly in Step 10, by refitting with those priors half and twice as wide.

Parameter recovery

Second, can the model find an effect we put there ourselves? We simulate three populations: one with no discrimination, one where women are penalized by 0.5 on the log-odds scale, and one where they’re penalized by 1. We fit the model to each and check whether the posterior covers the true value of the estimand.

Steps 5–8 again: a sex effect for each department

Step 5: Let the sex effect vary

The new model gives each department its own sex effect:

\[ \begin{align} \text{admitted}_i &\sim \mathrm{Bernoulli}(p_i) \\ \mathrm{logit}(p_i) &= \alpha + \beta_{\mathrm{sex}[i],\,\mathrm{dept}[i]} + \gamma_{\mathrm{dept}[i]} \\ \beta_{\mathrm{sex},\,\mathrm{dept}} &\sim \mathrm{Normal}(\bar\beta_{\mathrm{sex}}, \tau) \\ \bar\beta_{\mathrm{sex}} &\sim \mathrm{Normal}(0, 1) \\ \tau &\sim \mathrm{Half\text{-}Normal}(0, 0.5) \\ \alpha &\sim \mathrm{Normal}(0, 1.5) \\ \gamma_{\mathrm{dept}} &\sim \mathrm{Normal}(0, 1) \\ 0 &= \textstyle\sum_{\mathrm{sex}} \bar\beta = \sum_{\mathrm{sex}} \beta_{\cdot,\,\mathrm{dept}} = \sum_{\mathrm{dept}} \gamma \end{align} \]

The departments’ sex effects aren’t unrelated: they’re drawn from one distribution, around an average effect \(\bar\beta\) (the old \(\beta\)) with spread \(\tau\). The model learns \(\tau\) from the data. If departments treat women alike, \(\tau\) is near zero and we’re back to the first model. If they don’t, each department’s effect is estimated mostly from its own applicants. A department with few applicants of one sex, like B with its 25 women, is pulled toward the average. This is partial pooling: it lets departments differ without chasing the noise in small groups. The prior on \(\tau\) says the departments’ effects probably differ by a few tenths on the log-odds scale, and rarely by more than one.

Step 6: The Stan code

models/berkeley_varying.stan
// berkeley.stan, with a sex effect that varies by department
functions {
  // adjustment for sum_to_zero_vector[K] SDs
  real stz_correction(int K) {
    return inv_sqrt(1 - inv(K));
  }
}
data {
  // prior predictive toggle (skips likelihood calculations)
  int<lower=0, upper=1> prior_only;

  // prior scales
  real<lower=0> alpha_sd;
  real<lower=0> beta_sd;
  real<lower=0> tau_sd;
  real<lower=0> gamma_sd;

  // dimensions
  int<lower=1> n;
  int<lower=1> n_sex;
  int<lower=1> n_dept;

  // group indices
  array[n] int<lower=1, upper=n_sex> sex;
  array[n] int<lower=1, upper=n_dept> dept;

  // observed outcomes
  array[n] int<lower=0, upper=1> admitted;
}
transformed data {
  // each applicant's sex x department cell, as a position in to_vector(beta)
  array[n] int cell;
  for (i in 1 : n)
    cell[i] = sex[i] + n_sex * (dept[i] - 1);
}
parameters {
  real alpha;
  sum_to_zero_vector[n_sex] beta_bar; // average sex effect
  real<lower=0> tau; // how much the sex effect varies between departments
  array[n_dept] sum_to_zero_vector[n_sex] z; // each department's deviation, in units of tau
  sum_to_zero_vector[n_dept] gamma;
}
transformed parameters {
  // sex effect in each department: beta[s, d]
  matrix[n_sex, n_dept] beta;
  for (d in 1 : n_dept)
    beta[ : , d] = beta_bar + tau * z[d];
}
model {
  alpha ~ normal(0, alpha_sd);
  beta_bar ~ normal(0, beta_sd * stz_correction(n_sex));
  tau ~ normal(0, tau_sd);
  for (d in 1 : n_dept)
    z[d] ~ normal(0, stz_correction(n_sex));
  gamma ~ normal(0, gamma_sd * stz_correction(n_dept));

  vector[n] eta = alpha + to_vector(beta)[cell] + gamma[dept];
  if (!prior_only)
    admitted ~ bernoulli_logit(eta);
}
generated quantities {
  // admission probability for every sex x department cell
  matrix[n_sex, n_dept] p;
  for (s in 1 : n_sex)
    for (d in 1 : n_dept)
      p[s, d] = inv_logit(alpha + beta[s, d] + gamma[d]);
}
  • beta is now a matrix with a column for each department, built as beta_bar + tau * z. The sampler explores z, which is standard Normal, rather than beta itself. This is the same model written in a form that is easier to sample when \(\tau\) is small (a non-centered parameterization).
  • cell, in transformed data, is each applicant’s position in beta once its columns are stacked into one vector. It lets the linear predictor pick each applicant’s sex effect in one line, like gamma[dept].
  • p is the same sex × department matrix as before, so direct_effect() works unchanged.

Step 9: Compute the estimate

Now we can answer the question from Step 1. We compute the direct effect for every posterior draw of the second model. To see what the second pass changed, we compute it from the first model too, and, for the choice we made in Step 3, averaged over the women who applied instead of over all applicants:

Among applicants to the same department, there’s no sign that women are admitted less often than men. With a sex effect for each department, the estimate is +3.5 percentage points: being seen as a woman raises an applicant’s chance of admission, by between +0.7 and +6.4 points (90% interval). The probability that women are disadvantaged is 2%. The first model said +1.8. It understated the advantage for the same reason it understated the discrimination in the Step 7 simulation: it gave department A too little weight.

That advantage comes almost entirely from department A. Averaged over the women who applied, most of them to departments C–F, the effect is +0.5 points (−2.2 to +3.1): no difference either way. This is the choice from Step 3, and here it matters. We committed to averaging over all applicants, so our estimate stays +3.5. But a reader who cares about the women who actually applied should know that, for them, the answer is “no difference”. The two versions agree on the question we started with: departments don’t treat women worse than the men who apply alongside them.

Compare that with the overall gap: women were admitted 14 percentage points less often than men. That gap comes from where women apply, not from how departments treat them. That’s the pattern our Step 4 simulation produced in a world with no discrimination.

Step 10: Test its robustness

A result is only as good as the assumptions behind it, so we test how much it depends on them.

Sensitivity to priors

We refit the second model with different priors: the baseline and department priors (\(\alpha\), \(\gamma\)), which Step 7 found too wide, at half and twice their width; the sex-effect priors (\(\bar\beta\), \(\tau\)) at twice their width; and sex-effect priors so narrow that they all but rule out any difference between men and women. Because the prior scales are data, each variant is the same model with different numbers.

Making the baseline and department priors narrower or wider barely moves the estimate, and neither does widening the sex-effect priors: across those four fits, the median runs from +2.7 to +3.7 points. This confirms what we expected in Step 7: with thousands of applicants, the data outweigh the overly wide priors.

Only the last prior moves it, to +0.5 points. That prior says, before seeing any data, that no department’s sex effect can be more than a few hundredths on the log-odds scale. It overrides department A’s data because that’s what it was built to do. No one holds that belief, so it doesn’t weaken the result. What it shows is that the advantage for women rests on department A’s applicants, and that it takes a prior ruling such a difference out in advance to remove it.

Sensitivity to the DAG: an unobserved confounder

The strongest assumption we made is that, within each department, the men and women who apply are equally qualified. Step 2 gave two ways it could fail. Here they are in the DAG, with qualifications as U, a variable we can’t observe, and with Applied, which we condition on because the data hold only people who applied:

dag { Admitted [outcome,pos="2,0"] Applied [adjusted,pos="0.4,1.6"] Department [adjusted,pos="1,0.7"] Sex [exposure,pos="0,0"] U [latent,pos="1.6,1.6"] Department -> Admitted Sex -> Admitted Sex -> Applied Sex -> Department U -> Admitted U -> Applied U -> Department }

  • Selection into applying (\(\text{Sex} \to \text{Applied} \leftarrow U\)). Suppose women face barriers before they apply, so only the most qualified women apply at all. Then, within any department, the women are more qualified than the men. Comparing within departments would make women look favored even if departments discriminate against them.
  • Qualifications drive where people apply (\(\text{Sex} \to \text{Department} \leftarrow U\)). If strong applicants aim for the selective departments, then a man in a selective department is more likely to be a strong applicant than a woman there, since women apply to those departments anyway. Comparing within departments would make women look disadvantaged, even with no discrimination.

In both cases, the path runs through a variable we hold fixed, and holding it fixed is what makes men and women differ in U. We can test how much this matters by going back to the Step 4 simulation and adding U. Everything else stays the same. The new lines are marked.

Show code 
simulate_admissions_u <- function(
  n = 4500,
  discrimination = 0, # Sex -> Admitted: effect of being female, in log-odds
  depts = c("A", "B", "C", "D", "E", "F"),
  admit_rate = c(0.65, 0.60, 0.35, 0.33, 0.25, 0.07), # Department -> Admitted
  male_pref = c(0.31, 0.21, 0.12, 0.15, 0.07, 0.14), # Sex -> Department
  female_pref = c(0.06, 0.02, 0.32, 0.20, 0.21, 0.19), # Sex -> Department
  u_on_admit = 0, # new: how much qualifications matter for admission
  female_selection = 0, # new: how much more qualified female applicants are, in SDs
  u_on_dept = 0 # new: how strongly qualified applicants aim for selective departments
) {
  # one row per department (single values are recycled to every department)
  departments <- tibble(
    dept = fct(depts),
    discrimination,
    admit_rate,
    male_pref,
    female_pref
  )

  # Sex: 60% men, as in the real data
  sex <- sample(fct(c("male", "female")), n, replace = TRUE, prob = c(0.6, 0.4))

  # new: qualifications, shifted up for women when female_selection > 0
  u <- rnorm(n, mean = female_selection * (sex == "female"))

  # Sex, Qualifications -> Department (new: the tilt toward selective departments)
  selectivity <- -qlogis(departments$admit_rate)
  selectivity <- selectivity - mean(selectivity)
  dept <- map2_vec(sex, u, \(s, u_i) {
    pref <- if (s == "female") departments$female_pref else departments$male_pref
    sample(departments$dept, 1, prob = pref * exp(u_on_dept * u_i * selectivity))
  })

  # Department, Sex, Qualifications -> Admitted
  d <- match(dept, departments$dept)
  dept_rate <- departments$admit_rate[d]
  dept_discrimination <- departments$discrimination[d]
  log_odds <- qlogis(dept_rate) +
    dept_discrimination * (sex == "female") +
    u_on_admit * u # new
  admitted <- rbinom(n, 1, plogis(log_odds))

  tibble(dept, sex, dept_rate, dept_discrimination, u, admitted)
}

# the true direct effect now holds each applicant's qualifications fixed too
true_direct_effect_u <- function(sim, u_on_admit) {
  log_odds_male <- qlogis(sim$dept_rate) + u_on_admit * sim$u # new
  log_odds_female <- log_odds_male + sim$dept_discrimination
  mean(plogis(log_odds_female) - plogis(log_odds_male))
}

Now we build in real discrimination (−0.5 log-odds) in every department, make qualifications matter for admission, and try each failure in turn:

In every one of these worlds, departments discriminate against women (red ×). When men and women are equally qualified, the model finds the discrimination. The two failures from Step 2 push the estimate in opposite directions. If women applicants are half a standard deviation more qualified, the discrimination vanishes from the estimate, and at a full standard deviation women look clearly favored, by more than our real-data estimate (dotted line). If qualified applicants aim for the selective departments, the model finds more discrimination than there is.

So our real-data result is credible only to the extent that we believe the men and women who apply to the same department are similarly qualified. If they aren’t, the error could go either way, and how far depends on which story is true. The model can’t settle that question. It’s an argument about the world, and settling it would take more data, such as measures of applicant qualifications.

The result

Within departments, we find no evidence that women are disadvantaged, at least in the six departments in our data. Averaged over all applicants, as we decided in Step 3, being seen as a woman raises the chance of admission by +3.5 percentage points, almost all of it in department A. Averaged over the women who actually applied, there is no difference. The conclusion holds up across a range of priors, and only a prior that rules out any sex effect in advance removes the advantage. It rests on an assumption we can’t test with these data: that men and women who apply to the same department are similarly qualified. If that’s wrong, the error could go either way. The overall gap is real: women were admitted 14 percentage points less often than men. It runs through department choice, so the place to look is why women apply to more selective departments.
