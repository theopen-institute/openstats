A Bayesian Workflow

This document walks through a complete Bayesian workflow, from the first question to a result we can defend.

Imagine you’re in charge of admissions at a large university. You want to know if your admissions process is fair. You’ve got data from thousands of individual applicants. What now?

The workflow has ten steps in three parts.

Scientific model: what we believe about the world, before any statistics.

  1. Ask the question. Say in plain words what you want to know, and picture what the answer would look like.
  2. Draw the causal model (DAG). Write down what you assume causes what, based on what you know about the domain.
  3. Define the estimand. Use the DAG to turn your question into one exact number, before you touch the data.
  4. Simulate the population. Write a simulation that could produce data like yours.

Statistical model: the machinery that turns data into an estimate, tested where we already know the truth.

  1. Write the formal model. Derive the statistical model from the DAG, in math notation.
  2. Write the Stan code. Translate the formal model into a program.
  3. Test on simulated data. Check that the priors imply plausible data and that the model recovers parameters we already know.

Analysis: the real data, the estimate, and how far to trust it.

  1. Fit and validate the model. Run the sampler, check its diagnostics, and run posterior predictive checks. Can we trust the model?
  2. Compute the estimate. Use the fitted model to estimate the estimand from step 3.
  3. Test its robustness. How much does the estimate depend on our assumptions?

None of steps 1–7 fit the model to the real data. In principle, you could do all of them before collecting any. (Here, the simulation borrows realistic numbers from the data, but it doesn’t have to.)

The steps are numbered, but the workflow is a loop. If the model can’t recover known parameters in step 7, or can’t reproduce the data in step 8, go back and fix the statistical model. If the result in step 10 depends on an assumption you can’t defend, go back further, to the scientific model: the DAG or the simulation. Each of those failures teaches us something.

replace_indexes <- function(tbl, data, ...) {
  specs <- rlang::enquos(...)
  factor_levels <- lapply(data, levels)

  parse_spec <- function(q) {
    expr <- rlang::get_expr(q)

    if (rlang::is_symbol(expr)) {
      return(list(var = rlang::as_string(expr), dims = NULL))
    }

    if (rlang::is_call(expr, "[")) {
      var <- rlang::as_string(expr[[2]])
      dims <- vapply(as.list(expr)[-c(1, 2)], rlang::as_string, character(1))
      return(list(var = var, dims = dims))
    }

    stop("Invalid specification")
  }

  parsed <- lapply(specs, parse_spec)
  out <- tbl

  for (p in parsed) {
    var <- p$var
    dims <- p$dims
    if (is.null(dims)) {
      next
    }

    idx_pattern <- paste(rep("(\\d+)", length(dims)), collapse = ",")
    full_pattern <- paste0("^", var, "\\[", idx_pattern, "\\]$")

    out$variable <- vapply(
      out$variable,
      function(v) {
        if (!grepl(paste0("^", var, "\\["), v)) {
          return(v)
        }

        m <- stringr::str_match(v, full_pattern)
        if (all(is.na(m))) {
          return(v)
        }

        idx <- as.integer(m[1, -1])

        labels <- Map(
          function(dim, i) {
            lvls <- factor_levels[[dim]]
            if (is.null(lvls) || i > length(lvls)) {
              return(NA_character_)
            }
            lvls[i]
          },
          dims,
          idx
        )

        paste0(var, "[", paste(unlist(labels), collapse = ","), "]")
      },
      character(1)
    )
  }

  out
}

# Draw a DAG as a ggplot: a circle per variable, an arrow per direct cause.
#   edges:      c("S -> H", "H -> W")
#   pos:        list(S = c(0, 0), H = c(1, 1), W = c(2, 0))
#   labels:     full names drawn beside each node, e.g. c(S = "Sex")
#   above:      nodes whose label goes above the circle instead of below
#   left, right: nodes whose label goes beside the circle instead
#   highlight:  edges to draw in red (e.g. one path); the rest fade to gray
#   exposure, outcome, unobserved: node names to style
dag_plot <- function(
  edges,
  pos,
  labels = NULL,
  above = NULL,
  left = NULL,
  right = NULL,
  highlight = NULL,
  exposure = NULL,
  outcome = NULL,
  unobserved = NULL,
  r = 0.3,
  text_size = 9
) {
  ink <- "#16314d"
  blue <- "#1b91ff"
  red <- "#ff2c2d"
  gray <- "#999999"

  nodes <- tibble::tibble(
    name = names(pos),
    x = vapply(pos, `[`, numeric(1), 1),
    y = vapply(pos, `[`, numeric(1), 2)
  )
  nodes$fill <- ifelse(
    nodes$name %in% exposure,
    blue,
    ifelse(nodes$name %in% outcome, ink, "white")
  )
  nodes$text <- ifelse(nodes$fill == "white", ink, "white")
  nodes$linetype <- ifelse(nodes$name %in% unobserved, "dashed", "solid")
  nodes$label <- if (is.null(labels)) "" else unname(labels[nodes$name])
  nodes$label[is.na(nodes$label)] <- ""
  nodes$label_y <- ifelse(nodes$name %in% above, nodes$y + r + 0.12, nodes$y - r - 0.12)
  nodes$vjust <- ifelse(nodes$name %in% above, 0, 1)
  nodes$label_x <- nodes$x
  nodes$hjust <- 0.5
  side <- nodes$name %in% left
  nodes$label_x[side] <- nodes$x[side] - r - 0.12
  nodes$hjust[side] <- 1
  side <- nodes$name %in% right
  nodes$label_x[side] <- nodes$x[side] + r + 0.12
  nodes$hjust[side] <- 0
  side <- nodes$name %in% c(left, right)
  nodes$label_y[side] <- nodes$y[side]
  nodes$vjust[side] <- 0.5

  circles <- do.call(rbind, lapply(seq_len(nrow(nodes)), function(i) {
    t <- seq(0, 2 * pi, length.out = 61)
    data.frame(
      name = nodes$name[i],
      x = nodes$x[i] + r * cos(t),
      y = nodes$y[i] + r * sin(t),
      fill = nodes$fill[i],
      linetype = nodes$linetype[i]
    )
  }))

  # Arrows run between circle edges, not centers
  ends <- strsplit(gsub("\\s", "", edges), "->")
  from <- vapply(ends, `[`, character(1), 1)
  to <- vapply(ends, `[`, character(1), 2)
  x0 <- nodes$x[match(from, nodes$name)]
  y0 <- nodes$y[match(from, nodes$name)]
  x1 <- nodes$x[match(to, nodes$name)]
  y1 <- nodes$y[match(to, nodes$name)]
  len <- sqrt((x1 - x0)^2 + (y1 - y0)^2)
  gap <- r + 0.04
  arrows <- data.frame(
    x = x0 + (x1 - x0) * gap / len,
    y = y0 + (y1 - y0) * gap / len,
    xend = x1 - (x1 - x0) * gap / len,
    yend = y1 - (y1 - y0) * gap / len,
    color = if (is.null(highlight)) {
      ink
    } else {
      ifelse(paste0(from, "->", to) %in% gsub("\\s", "", highlight), red, gray)
    }
  )

  ggplot2::ggplot() +
    ggplot2::geom_segment(
      data = arrows,
      ggplot2::aes(x, y, xend = xend, yend = yend, color = I(color)),
      linewidth = 1.6,
      arrow = ggplot2::arrow(length = ggplot2::unit(0.18, "inches"), type = "closed")
    ) +
    ggplot2::geom_polygon(
      data = circles,
      ggplot2::aes(x, y, group = name, fill = I(fill), linetype = I(linetype)),
      color = ink,
      linewidth = 1.2
    ) +
    ggplot2::geom_text(
      data = nodes,
      ggplot2::aes(x, y, label = name, color = I(text)),
      size = text_size,
      fontface = "bold"
    ) +
    ggplot2::geom_text(
      data = nodes,
      ggplot2::aes(label_x, label_y, label = label, hjust = hjust, vjust = vjust),
      color = ink,
      size = text_size * 0.75
    ) +
    ggplot2::coord_equal(clip = "off") +
    ggplot2::scale_x_continuous(
      expand = ggplot2::expansion(add = c(
        if (is.null(left)) 0.6 else 1.8,
        if (is.null(right)) 0.6 else 1.8
      ))
    ) +
    ggplot2::scale_y_continuous(expand = ggplot2::expansion(add = 0.6)) +
    ggplot2::theme_void()
}

Scientific model

Step 1: Ask the question

Start with the question as you’d say it out loud: is our admissions process unfair to women? You don’t need technical terms yet. You do need a clear picture of what the answer would look like.

A good way to get one is a thought experiment. Take a single applicant and change only the sex on their form. Keep their grades, their letters and the department they applied to the same. Would their chance of getting in change? If it would, the process treats people differently because of their sex. That’s what we mean by unfair.

We can’t run this experiment on real applicants, but it tells us what we’re looking for. We’ll come back to it in Step 4, where we run it on a simulated population.

Step 2: Draw the causal model (DAG)

A causal model contains no numbers. It’s a picture of the variables and of which ones cause which. You’ll hear it called a DAG (Directed Acyclic Graph), which is a complicated name for a simple idea.

dag { Admitted [outcome,pos="-0.619,0.077"] Department [exposure,pos="-0.858,0.192"] Sex [exposure,pos="-1.059,-0.272"] Department -> Admitted Sex -> Admitted Sex -> Department }

How do you pick these variables? You use what you already know about the subject. Here, we include sex because sex-based discrimination is a major social issue. We include department because some departments are much harder to get into than others.

These are theoretical choices, not empirical ones. The data can’t tell us which variables we should put in the graph or which way the arrows should point. We make these decisions on the basis of our past experience, previous research, and the consensus of the field. Very different DAGs can fit the same data equally well. The DAG comes from our understanding of how admissions work, and we have to commit to it before the data can say anything.

The choices also decide the answer. Every arrow is an assumption, and every missing arrow is an assumption too, usually a stronger one. Together they determine which variables the model includes, which comparison we make, and what the final number means. Suppose we had left department out. The DAG would then say to compare overall admission rates for men and women, and that comparison gives a very different answer from the one we’ll get here. Change the DAG and you will almost certainly change the result.

The DAG also leaves things out. Many other factors affect admission. The most obvious is an applicant’s qualifications: their undergraduate grades, test scores, letters of recommendation and research experience. Others include how well their interests match a faculty member’s, whether they need funding, and how they come across in an interview. Leaving a factor off the graph is safe only if two things are true: it isn’t related to sex, and it doesn’t affect both where people apply and whether they’re admitted. Qualifications can easily fail the second test. Strong applicants may apply to more selective departments, and they’re also more likely to get in. Because we compare men and women within departments, a factor like that can create a gap between them even when there’s no discrimination. So we’re assuming that, within each department, the men and women who apply are equally qualified. That’s a strong assumption, and the data can’t check it for us. In Step 10 we’ll see how much the result moves if it’s wrong.

This DAG is not the final word, and no DAG ever will be. There is no “right” model waiting to be found at the end of the process. Every DAG is a simplification. Each one brings some parts of the problem into focus and leaves others out. This one helps us see how department choice can hide or create a gap between men and women. It says nothing about what happens before anyone applies: who is encouraged to apply, who can afford to, and who expects to be welcome. A different DAG would bring those questions into view and push others out.

That doesn’t mean every DAG is as good as any other. Some fit what we know far better, and the data can rule some out. But the value of this workflow comes from going around the loop: drawing a DAG, seeing what it implies, finding where it fails, and drawing a better one. Each pass shows us something about the problem that we couldn’t see before. We never finish. We just understand more each time.

Step 3: Define the estimand

The DAG shows that our plain-language question has more than one meaning. Sex reaches admission along two paths:

  • A direct path, \(\text{Sex} \to \text{Admitted}\): departments treat women differently from men who apply to the same department.
  • An indirect path, \(\text{Sex} \to \text{Department} \to \text{Admitted}\): women apply to different departments, and those departments admit fewer people.

Suppose women are admitted at a lower rate overall. That gap could come from either path, and each one calls for a different fix. So “is admissions unfair?” is still too vague to estimate. We have to choose which path we’re asking about.

We choose based on what we’re responsible for, not on what’s easiest to estimate. As the admissions office, we control the decisions departments make, so we’ll focus on the direct path. This is the thought experiment from Step 1: change the applicant’s sex and keep their department the same. Written as a number to estimate, it’s the estimand:

Estimand: the average difference in admission probability between women and men who apply to the same department, averaged across departments in proportion to how many people apply to each.

We’ll measure it as a difference in admission rates. For example, a result of −0.05 would mean women are admitted 5 percentage points less often than men who apply to the same department.

Comparing applicants to the same department means we have to condition on department, so department has to go into the model. Settling the estimand before we write any code tells us what the model has to include and what we’ll compute from it at the end.

Step 4: Simulate the population

Before writing a statistical model, we write a generative one: a simulation that follows the DAG and produces fake applicants. This makes us state precisely how we think the data come about. Later, it gives us data where we know the right answer.

Show code 
# Each assumption is an argument, with a default based on the real data. Change them to
# simulate a different world. admit_rate, male_pref and female_pref give one value per
# department, in the order of depts, or a single value for all of them: admit_rate = 0.4
# means every department admits 40%.
simulate_admissions <- function(
  n = 4500,
  discrimination = 0, # Sex -> Admitted: effect of being female, in log-odds
  depts = c("A", "B", "C", "D", "E", "F"),
  admit_rate = c(0.65, 0.60, 0.35, 0.33, 0.25, 0.07), # Department -> Admitted
  male_pref = c(0.31, 0.21, 0.12, 0.15, 0.07, 0.14), # Sex -> Department
  female_pref = c(0.06, 0.02, 0.32, 0.20, 0.21, 0.19) # Sex -> Department
) {
  # one row per department (single values are recycled to every department)
  departments <- tibble(dept = fct(depts), admit_rate, male_pref, female_pref)

  # Sex: 60% men, as in the real data
  sex <- sample(fct(c("male", "female")), n, replace = TRUE, prob = c(0.6, 0.4))

  # Sex -> Department
  dept <- if_else(
    sex == "female",
    sample(departments$dept, n, replace = TRUE, prob = departments$female_pref),
    sample(departments$dept, n, replace = TRUE, prob = departments$male_pref)
  )

  # Department, Sex -> Admitted
  dept_rate <- departments$admit_rate[match(dept, departments$dept)]
  log_odds <- qlogis(dept_rate) + discrimination * (sex == "female")
  admitted <- rbinom(n, 1, plogis(log_odds))

  tibble(dept, sex, dept_rate, admitted)
}

Let’s simulate a world with no discrimination at all: within every department, men and women are admitted at the same rate. Women just tend to apply to more selective departments.

Show code 
sim_fair <- simulate_admissions(discrimination = 0)

# overall admission rates by sex
sim_fair |>
  group_by(sex) |>
  summarise(applicants = n(), admit_rate = mean(admitted))

Women are admitted much less often overall, even though the simulation contains no discrimination. The whole gap comes from the indirect path through department. This is why the estimand has to be defined within departments, and why department belongs in the model. If we compared overall rates, we’d find a gap that isn’t there.

Exploring other worlds

Every assumption in the simulation is an argument we can change. That lets us ask “what if?” questions about how the gap arises. Here we keep discrimination at zero and change one assumption at a time:

The overall gap disappears in both new worlds. It needs two things at once: men and women applying to different departments, and departments that differ in how selective they are. Remove either one and the gap goes away. Try other values yourself. What happens if women prefer the least selective departments? What if one department admits almost everyone?

Statistical model

Step 5: Write the formal model

Next, we turn the DAG into a statistical model:

\[ \begin{align} \text{admitted}_i &\sim \mathrm{Bernoulli}(p_i) \\ \mathrm{logit}(p_i) &= \alpha + \beta_{\mathrm{sex}[i]} + \gamma_{\mathrm{dept}[i]} \\ \alpha &\sim \mathrm{Normal}(0, 1.5) \\ \beta_{\mathrm{sex}} &\sim \mathrm{Normal}(0, 1) \\ \gamma_{\mathrm{dept}} &\sim \mathrm{Normal}(0, 1) \\ 0 &= \textstyle\sum_{\mathrm{sex}} \beta = \sum_{\mathrm{dept}} \gamma \end{align} \]

It looks complicated, but it has four parts:

  1. A likelihood (line 1): how randomness enters. Each applicant is admitted or not.
  2. A linear predictor (line 2): how the arrows in the DAG combine. There’s a baseline \(\alpha\), a sex effect \(\beta\), and a department effect \(\gamma\).
  3. Priors (lines 3–5): what we believe before we see the data.
  4. Constraints (line 6): each set of effects adds up to zero. Without this, the model couldn’t tell its parts apart. Adding 1 to \(\alpha\) and subtracting 1 from every \(\gamma\) would give exactly the same predictions. With the constraint, \(\alpha\) is the overall average and every other term is a deviation from it.

Each term in the model matches a piece of the DAG. Sex and department both point into admission, so both appear in the linear predictor. The estimand from Step 3 comes from \(\beta\), the term that lets women’s and men’s chances differ within a department.

The model also makes a simplifying assumption: the sex effect \(\beta\) is the same in every department. That keeps the model small. We’ll find out in Step 8 whether the data go along with it.

Step 6: Write the Stan code

Now we translate the formal model into a program the computer can run:

models/berkeley.stan
functions {
  // adjustment for sum_to_zero_vector[K] SDs
  real stz_correction(int K) {
    return inv_sqrt(1 - inv(K));
  }
}
data {
  // prior predictive toggle (skips likelihood calculations)
  int<lower=0, upper=1> prior_only;
  
  // dimensions
  int<lower=1> n;
  int<lower=1> n_sex;
  int<lower=1> n_dept;
  
  // group indices
  array[n] int<lower=1, upper=n_sex> sex;
  array[n] int<lower=1, upper=n_dept> dept;
  
  // observed outcomes
  array[n] int<lower=0, upper=1> admitted;
}
parameters {
  real alpha;
  sum_to_zero_vector[n_sex] beta;
  sum_to_zero_vector[n_dept] gamma;
}
model {
  alpha ~ normal(0, 1.5);
  beta ~ normal(0, 1 * stz_correction(n_sex));
  gamma ~ normal(0, 1 * stz_correction(n_dept));
  
  vector[n] eta = alpha + beta[sex] + gamma[dept];
  if (!prior_only) 
    admitted ~ bernoulli_logit(eta);
}
generated quantities {
  // admission probability for every sex x department cell
  matrix[n_sex, n_dept] p;
  for (s in 1 : n_sex) 
    for (d in 1 : n_dept) 
      p[s, d] = inv_logit(alpha + beta[s] + gamma[d]);
}

A few details:

  • The priors are written directly in the model block, exactly as in the formal model.
  • Stan enforces the constraints with sum_to_zero_vector. Forcing effects to sum to zero shrinks their spread, so the code widens each prior’s scale to compensate. That way, each effect’s prior matches the formal model.
  • The prior_only switch skips the likelihood. With it on, the model samples from the priors alone, which is what we need for prior predictive checks.
  • generated quantities reports the admission probability for every sex × department cell. We’ll compute the estimand from these.

berkeley <- cmdstan_model("models/berkeley.stan", dir = ".stancache")

fit_model <- function(data, prior_only = 0, model = berkeley) {
  data |>
    select(dept, sex, admitted) |>
    compose_data() |>
    c(list(prior_only = prior_only)) |>
    model$sample(seed = 2026, refresh = 0, show_messages = FALSE)
}

# the estimand from Step 3, computed for every posterior draw
direct_effect <- function(fit, data = df) {
  weights <- data |>
    count(dept) |>
    mutate(w = n / sum(n)) |>
    pull(w)

  fit |>
    spread_draws(p[sex, dept]) |>
    mutate(sex = levels(data$sex)[sex]) |>
    pivot_wider(names_from = sex, values_from = p) |>
    mutate(w = weights[dept]) |>
    group_by(.draw) |>
    summarise(direct_effect = sum(w * (female - male)))
}

Step 7: Test on simulated data

We test the model on data where we already know the answer before we trust it on data where we don’t. There are two checks.

Prior predictive check

First, do the priors imply plausible data? We run the model with prior_only = 1 and look at the admission rates it expects before seeing any data.

The prior on the direct effect is centered on zero, so it doesn’t assume discrimination in either direction. It’s also wide: gaps of 50 percentage points or more either way are allowed.

The admission rates show a problem. The priors pile up near 0% and 100%. That happens because three Normal priors add up on the log-odds scale, and a log-odds of ±3 is already 5% or 95%. These priors are looser than our actual knowledge: we don’t believe departments admit nearly everyone or nearly no one. This is a judgment call. We could tighten \(\alpha\) and \(\gamma\) now. With thousands of applicants, we expect the data to outweigh the priors, so we’ll keep them and check that expectation directly in Step 10.

Parameter recovery

Second, can the model find an effect we put there ourselves? We simulate three populations: one with no discrimination, one where women are penalized by 0.5 on the log-odds scale, and one where they’re penalized by 1. We fit the model to each and check whether the posterior covers the true value of the estimand.

Show code 
# the true value of the estimand: switch each applicant's sex, keep everything else the
# same, and average the change in their chance of admission
true_direct_effect <- function(sim, discrimination) {
  log_odds_male <- qlogis(sim$dept_rate)
  log_odds_female <- log_odds_male + discrimination
  mean(plogis(log_odds_female) - plogis(log_odds_male))
}

recovery <- tibble(discrimination = c(0, -0.5, -1)) |>
  mutate(
    sim = map(discrimination, \(b) simulate_admissions(discrimination = b)),
    truth = map2_dbl(sim, discrimination, true_direct_effect),
    estimate = map(sim, \(s) direct_effect(fit_model(s), data = s))
  )

In each case, the true value falls inside the posterior. The model and the estimand code work, at least in a world that matches our assumptions. If they didn’t, we’d have a bug or an identification problem, and we’d fix it here, where we know the right answer. Any single simulated dataset is noisy, so a more thorough version of this check repeats it many times with random true values. That’s called simulation-based calibration.

Analysis

Step 8: Fit and validate the model

Step 10: Test its robustness

A result is only as good as the assumptions behind it, so we test how much it depends on them.

Sensitivity to priors

We refit with a much tighter and a much looser prior on the sex effect. Each variant is the same model with one line changed: the scale in the prior on beta.

Sensitivity to the DAG: an unobserved confounder

The strongest assumption we made is that the factors left out of the DAG aren’t related to sex: men and women who apply are equally qualified. Suppose that’s wrong. Suppose women face barriers before they apply, so only the most qualified women apply at all. Then, within any department, the women are more qualified than the men. Comparing within departments would make women look favored even if departments discriminate against them.

We can test how much this matters by going back to the Step 4 simulation and adding the variable our DAG leaves out: qualifications, u. Everything else stays the same. The new lines are marked.

Show code 
simulate_admissions_u <- function(
  n = 4500,
  discrimination = 0, # Sex -> Admitted: effect of being female, in log-odds
  depts = c("A", "B", "C", "D", "E", "F"),
  admit_rate = c(0.65, 0.60, 0.35, 0.33, 0.25, 0.07), # Department -> Admitted
  male_pref = c(0.31, 0.21, 0.12, 0.15, 0.07, 0.14), # Sex -> Department
  female_pref = c(0.06, 0.02, 0.32, 0.20, 0.21, 0.19), # Sex -> Department
  u_on_admit = 0, # new: how much qualifications matter for admission
  female_selection = 0 # new: how much more qualified female applicants are, in SDs
) {
  # one row per department (single values are recycled to every department)
  departments <- tibble(dept = fct(depts), admit_rate, male_pref, female_pref)

  # Sex: 60% men, as in the real data
  sex <- sample(fct(c("male", "female")), n, replace = TRUE, prob = c(0.6, 0.4))

  # new: qualifications, shifted up for women when female_selection > 0
  u <- rnorm(n, mean = female_selection * (sex == "female"))

  # Sex -> Department
  dept <- if_else(
    sex == "female",
    sample(departments$dept, n, replace = TRUE, prob = departments$female_pref),
    sample(departments$dept, n, replace = TRUE, prob = departments$male_pref)
  )

  # Department, Sex, Qualifications -> Admitted
  dept_rate <- departments$admit_rate[match(dept, departments$dept)]
  log_odds <- qlogis(dept_rate) +
    discrimination * (sex == "female") +
    u_on_admit * u # new
  admitted <- rbinom(n, 1, plogis(log_odds))

  tibble(dept, sex, dept_rate, u, admitted)
}

# the true direct effect now holds each applicant's qualifications fixed too
true_direct_effect_u <- function(sim, discrimination, u_on_admit) {
  log_odds_male <- qlogis(sim$dept_rate) + u_on_admit * sim$u # new
  log_odds_female <- log_odds_male + discrimination
  mean(plogis(log_odds_female) - plogis(log_odds_male))
}

Now we build in real discrimination (−0.5 log-odds), make qualifications matter for admission, and vary how much more qualified the female applicants are:

In every one of these simulations, departments discriminate against women (red ×). When applicants are equally qualified, the model finds the discrimination. If women applicants are half a standard deviation more qualified, the model misses most of the discrimination: the estimate shrinks toward zero. At a full standard deviation, women look clearly favored, by even more than our real-data estimate (dotted line).

So our real-data result, “no direct disadvantage for women”, is credible only to the extent that we believe male and female applicants are similarly qualified. The model can’t settle that question. It’s an argument about the world, and settling it would take more data, such as measures of applicant qualifications.

The result

Within departments, we find no evidence that women are disadvantaged. If anything, they’re admitted about 2 percentage points more often. The conclusion holds up across a wide range of priors. It comes with two caveats. First, the model averages over departments, and department A doesn’t fit that average well. Second, it rests on an assumption we can’t test with this data: that male and female applicants are similarly qualified. The overall gap is real. It runs through department choice, so the place to look is why women apply to more selective departments.
